# ChatGPT의 업무방 현황판 참여 설계 (시험 단계)

> 상태: **시험 단계.** 이 문서만으로 ChatGPT 세션이 자동 접속하거나 상시 실행되는 것은 아닙니다.

## 목적과 역할

- **ChatGPT(외부 대화 참여자)**: 사용자가 ChatGPT 대화창에서 요청할 때 비공개 업무방 동기화 저장소의 세션 현황 및 회의록을 읽고, 최신 변경 사항을 요약합니다.
- **의장(총괄 Claude Code 세션)**: 프로젝트 지시를 검토·분배하는 기존 총괄 역할을 그대로 유지합니다.
- **사용자**: ChatGPT 참여 여부와 지시 범위를 결정합니다. ChatGPT가 의장을 대체하거나 사용자 승인 절차를 건너뛰지 않습니다.

## 통신 경로

1. ChatGPT는 사용자의 요청에 따라 GitHub 연결로 비공개 동기화 저장소의 `main/minutes/` 및 `m/<machine-key>/` 상태를 읽을 수 있습니다.
2. 세션에 **실제 지시를 보내는 경로는 회의록이 아닙니다**. `workroom/sync.js`의 수신 처리 규약은 발신자의 `m/<sender-key>` 브랜치에 `send/<recipient-machine-key>/<message-id>.json` 파일을 만들도록 정의합니다.
3. 수신 컴퓨터의 `sync.js`가 해당 파일을 가져와 `send.js`를 통해 대상 세션에 입력합니다. 이때 세션 ID(`sid`), 보낸 시각(`at` 밀리초), 메시지 내용(`text`), 발신/수신 컴퓨터 식별 정보가 필요합니다.
4. 수신측은 `receipts/<message-id>.json`에 처리 결과를 남길 수 있습니다. **GitHub 커밋 완료와 세션 수신 성공은 서로 다릅니다.** 발신 측은 수신 확인이 없으면 '대기 중'으로 알려야 합니다.
5. `sync.js`는 전송 시각에서 **2시간 이상 경과한 새 지시를 거부**합니다. 실험 시에는 현재 시각을 사용하고, 중복 전송을 방지하려면 고유 메시지 ID를 써야 합니다.

## 운영 원칙

- ChatGPT는 사용자가 해당 대화에서 구체적으로 지시한 경우에만 메시지를 보냅니다. 단순히 이 문서에 역할이 존재한다는 이유로 상시 접근 권한이나 자동 지시 권한이 생기지 않습니다.
- **최초 시험**: 의장에게 읽기·쓰기 연동 가능성을 확인하는 메시지만 보내고, 의장이 사용자에게 직접 수신/가능 여부를 보고하도록 합니다. 사용자가 의장에게 **OK**로 참여를 승인하기 전에는 지속적 참여나 후속 자동 지시를 활성화하지 않습니다.
- GitHub 접근·수정 요청이 별도 승인을 요구하면 해당 앱/플랫폼의 승인을 따라야 합니다. 문서에 적혀 있다는 것만으로 승인 정책이 무효화되지는 않습니다.
- 민감한 업무 데이터와 토큰은 공개 `AI-news` 저장소에 쓰지 않습니다. 시험 메시지와 세션 교신 데이터는 비공개 동기화 저장소에만 둡니다.
- 장시간 ChatGPT 대화는 종료될 수 있으므로, 장기 진행상황은 작업 메모/커밋/회의록에 보관합니다. 새 대화창에서는 저장된 기록을 명시적으로 다시 읽고 이어갑니다.

## 확인해야 할 항목

- [ ] 발신 브랜치 및 메시지 JSON이 정상 커밋됨
- [ ] 수신측 동기화가 해당 메시지를 가져옴
- [ ] 수신측 `receipts/`로 정상 처리 여부 확인됨
- [ ] 의장이 사용자에게 실제로 확인 메시지를 전달함
- [ ] 사용자가 의장에게 참여 허용을 별도로 명시함

실제 연동 동작은 `workroom/send.js`와 `workroom/sync.js`가 기준이며, 문서와 코드가 충돌하면 코드가 정한 절차를 확인해야 합니다.
